# Auto-Chemyth ⚗️

化学を題材にしたオートバトラー（オートチェス系）ゲーム。ビルド不要の静的サイトで、GitHub Pages でそのまま動く。

- 41種の元素・化合物（コスト1〜5）、14種のシナジー（族・性質）、15種の実験器具、12種の研究テーマ
- 7人のライバルAIと共有プールで対戦（ショップ／利息／連勝・連敗／レベル／★合成）
- **オンライン対戦**：友だちとルームを作って2〜8人で対戦（空き席はライバルAI。常に8人）
- スキルは実際の反応式に基づく：中和、イオン化傾向、不動態、脱水、けん化、王水 など
- 舞台は化学アカデミーの「元素盤」。全41種＋実験ラウンドの敵4種に、物質の色・状態に基づく化身フィギュア（手続き生成SVG、画像ファイルなし）
- PC（ドラッグ＆キー操作）／スマホ（タッチ）両対応

## 公開方法
リポジトリの Settings → Pages → Source を「Deploy from a branch」にし、公開したいブランチの `/ (root)` を選ぶ。

## ローカルで動かす
```
python3 -m http.server 8000   # → http://localhost:8000
node test/sim.mjs 20          # ヘッドレスで全ゲームを回すバランス確認
```

## オンライン対戦のしくみ
- タイトルで「オンライン」→ 表示名を入れて **ルームを作る**（5文字のコードと招待リンク `?room=CODE` が出る）か **コードで参加**。招待リンクを開くと参加画面から始まる。
- ロビーではホスト（ルーム作成者）がライバルAIの強さを選び「開始」。2〜8人、残りの席はAI。
- **ホスト権威**：本物の `Game` はホストのブラウザだけが動かす（`window.__G`）。他の人は購入・売却・リロード・経験値・ロック・配置・装備・研究テーマ・準備完了を「インテント」として送り、ホストがその席の状態（所持・ゴールド・フェーズ・範囲）で検証して適用し、状態のスナップショットを全員に配る。自分以外の席は操作できない。各端末は同じ検証関数で操作を即座に予測表示し、スナップショットで整合させる（ドラッグ中は描画を待つ）。
- 準備時間は常にホストが管理（全員が「準備完了」を押すと早く開始）。研究テーマは各自が準備時間内に選び、未選択なら自動で選ばれる。
- 戦闘は開始時にホストが全試合を決定論的シミュレーションで確定し、各試合の（両チーム・強化・乱数シード）と結果を1通で配る。各端末は自分の試合を同じ `Battle` で手元再生する（自分がチーム1なら盤面を180°回して描画）。オンラインの戦闘速度は×1固定。
- 切断したプレイヤーは次の準備フェーズからAIが代行。同じ端末で同じリンクを開くと（この端末で使った識別子を `localStorage` に記録）ゲーム中は席に戻れる。ホストが退出するとゲームは全員終了（ホスト移行はなし）。脱落しても接続したまま観戦でき、最後に全8人の順位が出る。

### 通信（Supabase Realtime）
- 使うのは Supabase Realtime の **Broadcast と Presence だけ**（テーブル・SQL・認証なし）。チャンネル名は `autochemyth:room:<CODE>`。
- `@supabase/supabase-js` は jsDelivr から版を固定して（`js/net/config.js`）、オンラインに入ったときだけ動的 `import()` する。ソロはネットワーク不要。
- 同報量を抑えるため、ホストのスナップショットは最短350ms間隔に間引き（フェーズ切替時は即時）、戦闘データは1ラウンド1通にまとめる。1通は数KB〜数十KBで、Broadcast の上限（無料枠256KB）より十分小さい。
- `?net=local` を付けると Supabase の代わりに同じブラウザ内の `BroadcastChannel` を使う（複数タブでの自動テスト用）。

### フォークして使う場合
1. 自分の Supabase プロジェクトを作り、`js/net/config.js` の `SUPABASE_URL` と `SUPABASE_KEY`（publishable key。公開前提の値）を書き換える。Realtime が有効なら追加設定は不要（テーブルもポリシーも使わない）。
2. 必要なら `CHANNEL_PREFIX` を変える（同じプロジェクトを他の用途と共有する場合の名前空間）。
3. 認証がないため、ルームコードを知っている人は誰でも参加・送信できる。友だち同士で遊ぶ前提の作り（下記の制限を参照）。

### 制限
- 識別子は認証されていないので、悪意ある参加者が他人の識別子を名乗ることは防げない（席の取り違えはホストが防ぐ）。スナップショットには全員のショップ・ゴールドも含まれる。
- ホストのタブがバックグラウンドで長時間止められると進行が遅れる。ホストが落ちるとゲームは終了する。

## 構成
| ファイル | 役割 |
|---|---|
| `js/data.js` | ユニット・シナジー・器具・研究テーマの定義 |
| `js/combat.js` | 戦闘シミュレーション（描画非依存） |
| `js/game.js` | 経済・ショップ・ラウンド進行・ライバルAI |
| `js/figures.js` | 化身フィギュアとシナジーアイコン（インラインSVGスプライト。`figure(id)` で `<use>` 参照を返す） |
| `js/lore.js` | 世界観テキスト（化身のひとこと・ライバルの称号）。表示専用でゲームの数値には影響しない |
| `js/ui.js` / `css/style.css` | 描画・ドラッグ操作・演出・ロビー |
| `js/intents.js` | プレイヤー操作の検証と適用（ソロ・ホスト・クライアント予測で共通） |
| `js/net/config.js` | Supabase の URL・公開鍵・ライブラリの版 |
| `js/net/transport.js` | 通信路（Supabase Realtime／同一ブラウザの BroadcastChannel） |
| `js/net/host.js` | ホストの権威サーバー（検証・スナップショット・ラウンド進行・切断処理） |
| `js/net/client.js` | クライアント（影の Game・予測・再適用） |
| `js/net/proto.js` | スナップショット、ルームコード、名前の正規化 |
| `js/net/session.js` | ルーム作成・参加の配線 |
